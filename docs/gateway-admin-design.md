# Hezuo 网关管理后台设计

## 范围与现状

面向网关运营者，不是桌面工作区后台。网关管理账号、AI 权限、积分、请求结算和连接状态；不读取桌面 bot、对话正文或工作区文件。

`/admin` 已实现账号权限、积分、请求结算和系统状态页面；接口契约见 [gateway-admin-api.md](gateway-admin-api.md)，部署与验证范围见 [gateway-deployment-193.md](gateway-deployment-193.md)。本文件保留功能边界和扩展接口要求。

## 页面与交互

统一入口 `/admin`，沿用网关同源账号登录。桌面布局为左侧导航、顶部环境与账号、右侧内容；窄屏导航收起。金额显示积分，内部使用整数微积分，1 积分 = 1,000,000 微积分。

### 账号与积分（首屏）

顶部为精确邮箱搜索，不默认拉取所有用户。查找后显示账号 ID、邮箱验证状态、AI 状态、可用积分与预占积分。主要操作为启用 AI、停用 AI、增加积分；右侧抽屉填写原因并确认。增加积分显示变更前余额和增加额，不提供覆盖余额或任意扣款。

账户下方展示请求记录，支持游标翻页，点击进入请求详情。空状态明确区分未搜索、账号不存在、账号无请求和接口失败。

### 请求与结算

按当前账号查看请求 ID、模型、状态、预占额、最终扣费、时间及错误码。待复核请求单独强调。详情页先展示实际用量证据，再允许输入最终扣费（不得超过预占额）和结算原因；零结算明确标为释放预占。提交前二次确认，不自动把网络错误解释为应退款。

### 系统状态

展示健康探针、网关地址、版本、邮箱能力及 AI 是否配置。健康探针仅代表网关存活，不代表桌面在线或上游可推理。证书信任说明单列；不展示密钥、会话令牌或数据库路径给普通账号。

### 后续扩展页面的接口约束

全局总览、用户列表、全局请求筛选、设备在线列表、模型定价编辑和完整审计日志当前缺少对应运营者接口，不能用普通账号接口冒充。正式实现这些页面时需同时增加运营者鉴权、分页、审计及契约验证；模型配置变更需要明确生效机制，不能仅写页面状态。

## API 对应

| 页面操作 | 已有 API | 约束 |
| --- | --- | --- |
| 登录能力 | `GET /v1/auth/methods` | 无邮件能力时不显示邮箱验证码入口 |
| 账号登录 | `/api/auth/*` | 沿用现有认证策略 |
| 当前账号 | `GET /v1/me` | 只证明已登录，不证明是运营者 |
| 按邮箱查询 | `GET /v1/operator/ai/account?email=…` | 精确匹配，服务端运营者校验 |
| 启停 AI | `POST /v1/operator/ai/account` | 原因、幂等操作 ID |
| 增加积分 | `POST /v1/operator/ai/balance` | 正向增加，原因、幂等操作 ID |
| 账号请求 | `GET /v1/operator/ai/requests?userId=…&cursor=…` | 游标分页 |
| 人工结算 | `POST /v1/operator/ai/requests/:id/settle` | 不超预占，不重复结算 |
| 健康状态 | `GET /healthz` | 不能当作业务全链路通过 |

需补充最小 `GET /v1/operator/me` 能力接口，使后台进入时即可明确区分 401 未登录和 403 非运营者，而不是靠任意邮箱查询探测权限。该接口不得返回配置秘密。

## 安全与错误处理

- 每个管理 API 独立校验运营者身份，隐藏按钮不是权限控制。
- 普通注册不自动获得运营者权限。初始管理员由服务器 CLI 对已注册邮箱显式授权。
- 优先复用同源安全会话；会话令牌不写 localStorage。采用 cookie 时，写操作必须验证来源并具备 CSRF 防护。
- 表单提交期间禁止重复点击；同一次提交的未知结果重试复用操作 ID。成功后重读服务端结果。
- 原因必填；审计记录包含操作者、对象、操作 ID、结果和时间，不含密码、上游 key 或会话令牌。
- 401 回登录，403 显示权限不足，409 显示状态已变化并刷新，429 提示稍后操作；5xx 保留输入但不虚报成功。
- 使用 CSP、无第三方脚本、输出转义；账号查询参数和响应不得进入访问日志明文留存。

## 验收

在独立临时数据库、真实 Worker 和假上游 fixture 中验证：运营者登录、普通账号拒绝、精确查询、启停权限、积分幂等增加、翻页、人工结算上界与重复提交。浏览器验证宽窄视口、键盘操作、错误和空状态。不得向生产用户账户注入验证积分或请求。
