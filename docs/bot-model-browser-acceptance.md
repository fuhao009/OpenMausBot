# Hezuo Bot 真实模型网页操作验收

## 本次测试目标

向项目自己的 Hezuo Bot 发送一句自然语言需求，由 Bot 调用真实模型，模型选择浏览器工具并打开测试网页。先只验证这一个动作，不执行填写、点击提交或其他业务操作。

本文是测试方案和报告要求，不是通过记录。

## 必须使用的链路

用户需求 → Hezuo 聊天界面 → Bot 服务 → product-ai 账号网关 → 真实模型 → 浏览器工具 → 目标网页 → 工具结果返回模型 → Bot 最终回复。

- 使用项目 Bot，不使用 Codex CLI 代替。
- 不用测试脚本直接调用浏览器工具代替模型决策。
- 不使用假模型、固定工具调用响应或预写操作顺序冒充真实模型。
- 模型配置来源和核对方法见 [193 网关部署记录](gateway-deployment-193.md)。以测试时 Bot/会话实际选择和实际请求为准，不把网关默认模型当作该 Bot 的模型。
- 按 [隔离验证规则](verification/README.md)准备独立测试环境和测试账号；假模型 fixture 只用于接线检查，不计入本次真实模型验收。不向正式会话发送测试消息，不复用正式浏览器 Cookie。
- 真实模型会消耗测试账号额度；不在报告、日志或截图中输出令牌、密码、密钥。

## 发给 Bot 的原始需求

将下面的地址替换为本次隔离测试网页的真实地址后，原样发送：

> 请在你的内置浏览器里打开这个测试网页：<测试网页地址>。打开后告诉我页面标题和页面显示的测试标识。只打开和读取，不进行其他操作。

不得向模型提供测试标识答案、CSS 选择器、元素引用、按钮坐标、工具名或预写步骤。测试驱动程序只能发送需求、观察事件和核对结果，不能替模型完成网页动作。

## 执行步骤和计时

计时使用单调时钟；时间戳用于定位日志，不以系统时钟差作为精确耗时。默认单次试验，报告中明确次数，不将一次测量当平均值或成功率。

| 步骤 | 动作 | 记录内容 | 耗时边界 |
| --- | --- | --- | --- |
| 1 | 向 Bot 发送需求 | 原文、Bot 名称与 ID、任务/会话 ID | 从提交到 Bot 服务确认接收 |
| 2 | Bot 请求真实模型 | 实际模型 ID、提供方、请求 ID（可取得时） | 从模型请求发出到响应/工具调用收齐 |
| 3 | 模型决定打开网页 | 实际工具名、脱敏参数、目标会话与页面 | 从工具开始到返回 |
| 4 | 浏览器加载目标网页 | 最终 URL、加载状态、页面错误 | 有独立加载事件则单列，否则注明包含在工具耗时内 |
| 5 | 模型读取并判断页面 | 实际读取工具、返回标题和标识；继续调用模型的每一轮 | 每次模型调用和每次工具调用分别记录 |
| 6 | 独立核对目标页面 | 从实际内嵌视图读取 URL、标题、标识，保存截图 | 从独立检查开始到完成 |
| 7 | Bot 最终回复 | 原始回复及其与页面证据是否一致 | 记录最终回复完成时间 |

- 端到端耗时：发送需求开始 → Bot 最终回复结束且独立页面验证完成，两者取较晚时间。
- 模型、工具、加载耗时可能包含或重叠，不能盲目相加作为总耗时。
- 模型无法直接计时的部分标注“未取得”，不得用整轮耗时推算。
- 权限审批、人工等待、错误和重试逐条记录。未经审批的动作不执行。
- 事先设置并记录有界的试验超时；超时即记为失败或阻塞，不隐去失败重跑。
- 环境准备耗时与 Bot 执行耗时分开，不混入模型推理时间。

## 成功判定

同时满足以下条件才通过：

1. 需求从项目 Bot 对话入口发出，并发生真实模型请求。
2. 浏览器工具调用由该次模型响应产生，而不是测试脚本指定。
3. 实际目标是本次绑定的可见内置 WebContentsView，而非其他独立浏览器或错误标签。
4. 内置页面 URL、标题和唯一测试标识与测试站点一致。
5. Bot 的回复与页面内容一致，并有截图及任务工具记录支持。
6. 没有执行要求之外的网页操作。

工具返回成功但页面没变化、模型只声称完成、操作到错误浏览器或无法证明使用真实模型，均不能判成功。隐藏窗口与可见窗口的结果不得混用。

## WebContentsView 实现契约与验收边界

以下是内嵌浏览器接线的实现契约与待验证要求，不是已通过记录。

- 桌面 Electron 主进程持有真正的 `WebContentsView`；Bot 服务通过显式注入的 embedded backend 连接该视图对应的 CDP 目标。桌面已选择该 backend 后，不得因创建、连接或导航失败而静默启动独立 Chrome。服务器未注入时保留原有浏览器路径，不据此声称桌面内嵌验收通过。
- 子进程发出 `hezuo:embedded-browser-open`，携带服务端确定的 profile key、fresh、viewport 和该 profile 的 egress 端口。主进程返回租约 `leaseId`、随机 generation、版本和 page limit；后续 CDP、release、closed 均按租约与 generation 配对。过期或其他租约的消息不能操作当前页面；超时、退出与重连必须释放旧租约，不能留下无限等待。
- profile、持久分区和下载目录由可信进程依据工作区及 profile 身份确定，不从 renderer 接收可任意指定的分区名、路径或 CDP target。页面网络仍经过 BrowserService 对应的 egress gate；不得为内嵌视图绕开账号隔离或本地网络限制。
- renderer 只提交 Bot、thread 和现有 stream 的 viewer ID。服务端重新解析 Bot/thread 对应的真实 profile，确认该 viewer 的 owner 与 person 均为 `local-owner`，再由私有父子进程通道返回绑定。renderer 声称的 profile、target 或“我已取得控制”不能作为授权依据。
- 原有 BrowserService 的 person hold、viewer 控制权和遮挡规则继续有效。原生输入只在该 viewer 可操作且实际控制浏览器时放行；其他人的 hold、控制权变更、viewer 断开、切换标签及浏览器关闭必须同步到原生视图，不得依赖截图或旧的授权快照继续输入或显示秘密页面。
- 内嵌 Chromium 是 headed 页面：CDP 连接不伪装独立 headless Chrome、不覆盖浏览器身份，初始 viewport 保持原生视图尺寸。文件上传及下载必须仍受服务端批准路径和租约目标范围约束。
- 恢复仅指 **URL-only restore**：可以重新打开允许恢复的标签 URL，不表示保留 DOM、JavaScript 堆、滚动位置、未提交表单、临时凭据或一次性操作状态；`fresh` 应打开干净页面。持久分区的站点存储与页面内存恢复是不同概念，报告必须分别描述。

接线验证可以使用隔离 fake-engine 检查租约、输入门禁、生命周期与网络策略，但它不能替代上文的真实模型 Bot 验收。最终证据必须证明模型工具调用操作的 CDP target 与用户看到的 WebContentsView 是同一页面；独立 Chrome、仅截图流、脚本直接导航成功或 backend 单元测试通过，均不能算本项通过。
