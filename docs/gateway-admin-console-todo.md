# 网关管理平台重新设计清单

面向服务端开发者。基线：`backend/gateway-beta`（193 部署 `8e54c107d`）。参考 new-api、sub2api 的后台功能，按本网关的内测范围取舍。

## 现状与差距

| 现有 | 缺什么 |
| --- | --- |
| 只能按完整邮箱查一个账号，没有用户列表 | 看不到有哪些用户、谁在用、谁余额低 |
| 请求记录只在单个账号下 | 没有全局请求日志；待复核页（S2）是唯一的跨账号视图 |
| 渠道、模型各一个表单，字段全部平铺 | 没有渠道连通性测试，没有健康状态，没有用量统计 |
| 智能计费一个长页面，倍率按基点填 | 没有趋势，没有调价历史 |
| 没有概览 | 一进来看不到网关是否健康、今天用了多少、有几笔待复核 |
| 没有审计查询、没有运营者管理、没有公告 | 排查和交接只能翻数据库 |
| 内测加积分只能一个账号一个账号加 | 没有批量发放，没有兑换码 |

## 范围与原则

- 做：内测运营需要的管理功能。
- 不做：在线支付、订阅套餐、邮件、OAuth 登录、Playground、多语言（后台只做简体中文）、渠道自动故障转移（见 P2，会违反不重放原则）。
- 只改 `gateway/` 和 `docs/gateway-*.md`。新增的运营接口都要有 `operatorId` 鉴权，普通账号返回 403。
- 保留现有后台的安全规则：Bearer 令牌只放内存、`credentials: "omit"`、变更两步确认并冻结 `operationId`、结果未知时用同一个 `operationId` 重试、密钥只写不回显、积分用精确整数微积分、不做四舍五入。
- 不展示、不存储对话内容和提示词。后台只看用量、扣费、状态、错误码。
- 技术约束不变：不用前端框架和构建步骤，CSP 不放宽（不用内联样式和脚本、不引外部字体和 CDN）。
- 页面和接口分开提交；每个页面的验收都要在隔离环境里用真实浏览器操作一遍，附截图。

## 视觉与交互规范

- 左侧导航 220px，窄屏收成顶栏。中性底色加一个品牌绿，字号 14px，数字等宽对齐。
- 列表统一：筛选条、可点击的行、右侧抽屉看详情和编辑、表头固定、分页用游标。
- 状态用小标签：已结算灰、待复核琥珀、处理中蓝、已停用红。
- 危险操作（停用、删除、重置密码、批量结算）一律走两步确认，写明影响范围。
- 有未保存的更改时，底部出现保存栏，写明有几项，要求填原因。
- 去掉英文小标题、编号和宣传语。

## 导航与页面

导航顺序：概览 · 用户 · 请求日志 · 渠道 · 模型与定价 · 智能计费 · 积分 · 审计 · 设置。

### 1. 概览（P0）
功能：
- 一排数据卡片：网关状态、今日请求数、今日扣费积分、今日估算成本和毛利率（样本不足时显示"样本不足"）、待复核数、活跃用户数。
- 近 7 天趋势：请求数、扣费积分、失败率（折线，用 SVG 画，不引图表库）。
- 模型分布、渠道健康（最近一次探测结果和错误率）。
- 待处理区：待复核请求、余额低于阈值的用户、启用失败的渠道，各显示前 5 条并链接到对应页面。

新增接口：`GET /v1/operator/overview?window=1d|7d`，只返回聚合数字。

验收：
- 隔离环境造 3 个用户、30 条请求（含失败和待复核），页面数字与账本合计一致。
- 窗口内没有数据时显示空状态，不显示 NaN。
- 普通账号调用接口返回 403。

### 2. 用户（P0）
功能：
- 用户列表：邮箱、状态（可用、已停用、未开通）、可用积分、冻结积分、最近请求时间、注册时间。支持按邮箱前缀搜索、按状态筛选、按余额排序、游标分页。
- 详情抽屉：账号信息、余额卡片、最近请求、已登记的桌面安装、操作按钮。
- 操作（都沿用两步确认）：增加积分、扣减积分（必须填原因，不能扣到负数）、启用或停用 AI、停用账号、匿名删除、重置密码（只显示一次临时密码）。
- 每个用户的并发上限和单次预算上限可以单独设置，留空用全局默认。
- 批量操作：勾选多个用户批量加积分（同一数额、同一原因，每个用户单独生成 `operationId` 并写审计）。

新增接口：`GET /v1/operator/ai/accounts?q=&state=&cursor=`；`POST /v1/operator/ai/account/limits`；`POST /v1/operator/ai/balance/batch`；扣减积分走现有 balance 接口，接受负数并校验不低于 0。

说明：这会放开"不默认列出全部用户"的限制。内测规模下可以接受，但接口仍要求运营者权限，且列表不返回对话内容。

验收：
- 列表分页 50 条一页，100 个用户翻页不重复、不遗漏。
- 搜索 `beta-` 只返回该前缀的账号，已匿名删除的账号不在默认列表里，可以用"含已删除"筛选看到。
- 批量加积分 3 个用户：3 个账号余额各加对，审计记录 3 条；重复提交同一批 `operationId` 不重复加。
- 扣减超过可用余额时返回 409，余额不变。
- 并发上限设为 1 的用户同时发两条请求，第二条返回 429 `ai_busy`。

### 3. 请求日志（P0）
功能：
- 全局请求列表：时间、用户、模型（请求模型和实际模型）、渠道、状态、预占、扣费、耗时、错误码或结算原因。
- 筛选：状态、模型、渠道、用户、时间范围、请求编号；顶部有"待复核（N）"快捷标签。
- 详情抽屉：用量（输入、缓存、输出）、计价快照、成本和证据、时间线（创建、结算）、复核结算按钮。
- 批量结算：勾选多笔待复核请求，批量按 0 结算，或逐笔指定金额。
- 导出：当前筛选结果导出 CSV（最多 5000 行，不含提示词）。

新增接口：`GET /v1/operator/ai/requests` 扩展筛选参数；`GET /v1/operator/ai/requests/export`。

验收：
- 请求编号精确查找能命中，输入前 8 位也能命中。
- 待复核标签的数量与"待复核页"一致。
- 导出的 CSV 行数、扣费合计与页面合计一致，不含邮箱以外的个人信息。
- 批量结算后，对应账号冻结归零，审计记录齐全。

### 4. 渠道（P0）
功能：
- 渠道列表：名称、ID、上游地址、状态（启用、停用、探测失败）、最近探测时间、近 1 小时请求数和失败率、密钥是否已配置。
- 每行操作：测试连通（只请求 `/models`，不发推理）、启用或停用、编辑、删除。
- 编辑在右侧抽屉里：地址、密钥（只写不回显）、备注。
- 渠道详情：发现的上游模型列表，可以一键"基于此上游模型新建公开模型"，带出上游模型 ID。
- 记录每次探测结果（时间、状态码、耗时、错误摘要），保留最近 50 条。

新增接口：`POST /v1/operator/channels/:id/test`（沿用现有 probe）；`GET /v1/operator/channels/:id/health`。

验收：
- 把密钥改错后测试连通，页面显示"鉴权失败"，网关日志里没有密钥明文。
- 停用渠道后，绑定它的模型从 `GET /v1/ai/models` 里消失，已有请求不受影响。
- 删除仍被模型引用的渠道返回 409，并列出引用它的模型。

### 5. 模型与定价（P0）
功能：
- 模型列表：显示名、公开 ID、渠道和上游模型、协议、输入、缓存、输出价格（积分/百万 token，按精确值显示）、上下文和输出上限、状态、默认标记。
- 编辑在右侧抽屉里：价格输入以"积分/百万 token"为单位，内部精确换算成微积分，换算不成整数就拒绝。
- 一键复制模型、上下线、设为默认。
- 价格预览：输入"输入 token 数和输出 token 数"，显示这条请求的预计扣费和预占。

验收：
- 价格 `0.55` 积分保存后，库里是 `550000` 微积分；`0.5500001` 被拒绝。
- 预览的数字与同样用量的真实请求结算一致。
- 下线默认模型时要求先选新的默认模型。

### 6. 智能计费（P0，已有，重做界面）
功能：
- 分四个标签：指标、策略、模型档案、采购价。
- 策略里毛利按百分比、倍率按"×"填，保存时精确换算成基点；换算不成整数就拒绝。
- 新增"调价历史"：每次倍率调整的时间、原因、前后值、样本数。
- 说明文字收进折叠区。

验收：
- 在页面上填 `50` %，库里是 `5000` 基点；填 `33.333` % 被拒绝。
- 调价历史里的最近一条与控制器审计一致。

### 7. 积分（P1）
功能：
- 流水页：全局积分流水（增加、扣减、结算、退回），可按用户、类型、时间筛选，可导出。
- 兑换码：批量生成（数量、面额、有效期、备注），列表显示状态（未使用、已使用、已过期、已作废），可作废；用户在桌面端输入兑换码充值。
- 兑换码只在生成时显示一次明文，库里存哈希。

新增接口：`POST /v1/operator/redemptions`、`GET /v1/operator/redemptions`、`POST /v1/operator/redemptions/:id/void`；`POST /v1/account/ai/redeem`（用户端）。

说明：用户端兑换需要电脑端配合，先做服务端和后台，电脑端放到后面。

验收：
- 同一个兑换码并发兑换两次，只成功一次，余额只加一次。
- 过期、已作废的兑换码返回明确的错误码。
- 数据库里查不到兑换码明文。
- 批量生成 100 个，导出文件与列表一致。

### 8. 审计（P1）
功能：运营者操作日志：时间、运营者、操作类型、对象、原因、`operationId`、结果。可按运营者、类型、对象、时间筛选。只读，不能删除。

新增接口：`GET /v1/operator/audit?...`。

验收：加积分、结算、停用、删除、重置密码、渠道和策略变更都能在这里查到；日志里没有密钥、密码、临时密码明文。

### 9. 设置（P1）
功能：
- 运营者管理：列出运营者，添加或移除（至少保留一个）。
- 注册策略：开放注册、仅邀请、关闭注册；邀请码的生成和作废。
- 公告：一条简短的维护或通知文字，桌面端登录后显示（桌面端另做）。
- 全局默认：并发上限、单次预算上限、余额低提醒阈值。
- 维护模式：开启后推理请求返回 503 `maintenance`，不预占、不扣费；后台和登录仍可用。

验收：
- 移除最后一个运营者被拒绝。
- 关闭注册后，新邮箱注册返回明确的错误码，老用户登录不受影响。
- 维护模式下发一条推理请求：返回 503，账本没有新记录。

### 10. 系统状态（P1，并入概览）
健康探针、版本、迁移状态、能力开关（密码登录、邮箱验证码、AI 配置）。保留现有说明文字，收进折叠区。

## P2（暂不做）
- 用户分组和分组倍率、按分组限定可用模型。
- 订阅套餐（周期额度）。
- 渠道多密钥轮询、优先级和权重。
- 渠道自动故障转移：只有在上游明确拒绝、没有计费、没有到达模型的情况下才允许改道，规则要先和负责人确认，不能对已可能到达上游的请求重发。
- 在线支付。

## 交付顺序
1. 概览、用户列表、全局请求日志（P0 的数据页）。
2. 渠道、模型与定价的新界面。
3. 智能计费重做。
4. P1：积分和兑换码、审计、设置。

每页单独提交，交回时附检查结果、隔离环境的截图，以及每条验收的实测数据。
