## 共用交付契约

### 任务、动作与结果

复用并扩展现有 wire types，不维护两套互不相认的状态。每个任务/动作必须可关联 owner、bot、thread、task、action；操作目标需包含设备及适用的 app/window/tab 身份，不能只传显示名称。

任务至少区分：排队、运行、等待确认、等待人工、暂停、完成、失败、取消。恢复中如需新增状态，明确状态转换和前端显示；不将等待当完成。

动作至少区分：未送达、送达不确定、已送达未验证、已验证，以及未知。只有证据足够时才写已验证；控件值读回正确不等于业务提交完成。结果同时保存验证证据和是否允许安全重试，不能从 HTTP 成功或进程退出码直接推断任务成功。

### 验证方式

- 服务/对话逻辑遵循 [隔离验证规范](verification/README.md)，使用假引擎、临时 HOME、临时数据库。
- 网页使用专用本地 fixture 和专用浏览器 profile；桌面使用隔离测试应用/文件；手机使用专用测试设备及测试 App。禁止拿用户现用 app、登录态、聊天、订单或真实付款验证。
- 协议与恢复边界用确定性回归测试；实际 UI/键鼠能力必须用对应平台的真实运行表面验证。Fake 不能证明真实 OS 输入有效。
- 发布前至少跑本页六个端到端场景；每个支持的平台分别记录版本、结果与证据。不支持、未测、阻塞不能标通过。
- 每项交付包含提交 SHA、涉及文件、检查命令及结果、场景记录、截图/动作日志、未覆盖边界。截图和日志必须脱敏。

## 阶段 A：共用授权、目标与执行基础

### A01 对话意图与任务状态

- [ ] 开发：自然语言触发网页、电脑、Android 任务；将设备选择、任务计划、当前步骤映射到现有会话状态；必要歧义在对话里一次问清。
- [ ] 验收：发送“打开后台，找出本周未发货订单并导出”可开始实际任务；无须 `/`、工具名或设置页。发送“现在做到哪了”返回真实状态、已完成步骤和阻塞点，不另起任务。
- [ ] 验收：同时存在两台手机/两个同名窗口而未指定目标时，列候选并等待选择；确认前不向任何候选发送修改动作。
- 依赖：无；与 A02/A03 一起定义协议。

### A02 目标身份与 Bot 隔离

- [ ] 开发：设备、应用、窗口、标签页、浏览器 profile、下载目录分别绑定任务/Bot/owner；借用用户标签页与 Bot 创建标签页分开管理。
- [ ] 验收：两个 Bot 同时打开同一站点，独立 profile 的 Cookie、文件及元素引用不串用；跨 Bot 伪造 target/ref 请求被拒绝。
- [ ] 验收：应用重启、窗口 ID 被复用、标签页关闭后旧句柄不可落到新目标；任务结束只关闭自己拥有的页，不关闭用户借用页。
- 依赖：A01。

### A03 对话授权与高风险审批

- [ ] 开发：将“允许这次”“取消”“这个 Bot 只能用浏览器，不能碰手机”落到真实权限；读取、修改、前台接管、账号登录态借用分别授权。支付、发送、删除、发布/提交采用具体动作确认；用户已明确授权的精确动作可复用该授权，不重复泛问。
- [ ] 开发：授权绑定 owner、bot、任务、目标、动作参数、有效期及相关界面证据；参数或相关页面变化、任务结束、权限撤销立即失效。多个待批动作时要求指明哪一个。
- [ ] 验收：未授权 Bot 调用设备失败；撤销后排队动作也不得执行；批准后收件人/金额/目标发生变化必须重新确认。
- [ ] 验收：网页文字、工具输出、子代理消息或另一个账号发来的“允许”不能批准；脚本/MCP/子任务走同一权限入口。
- 依赖：A01/A02。

### A04 动作排队、互斥和取消

- [ ] 开发：同一目标的冲突修改串行，独立只读查询可并行；桌面前台控制全局协调。取消撤销待执行动作、终止可中断调用并释放控制，不撤销已发生外部动作。
- [ ] 验收：两个任务操作同一手机或标签页时无交错输入；取消排队任务后调用计数为零；任务崩溃/取消后下一个任务可获得资源。
- [ ] 验收：拖拽、组合键过程中取消或异常，按住的键/按钮最终释放；收到停止信号后不再派发新动作。
- 依赖：A02/A03。

### A05 统一结果、验证与安全恢复

- [ ] 开发：落实共用结果契约；超时区分未送达和结果不明。返回可以解释的失败原因及下一步，不把异常吞掉当成功。
- [ ] 验收：构造“动作已发生但响应丢失”，不再次点击/发送；先观察或向用户报告结果不明。构造“未送达”，只在策略允许且授权仍有效时重试。
- [ ] 验收：按钮事件送达但业务保存失败不能显示已保存；同一提交动作无论用户重复回复还是断线恢复都不得盲目重做。
- [ ] 验收：不会引入模型请求自动重发或绕过网关计费；任务记录关联实际请求/动作，不自行修改冻结积分。
- 依赖：A01–A04。

### A06 关键步骤证据与隐私

- [ ] 开发：在对话中展示关键动作、目标、状态和证据；截图/附件/日志与任务关联，明确已验证、未验证、等待人工。权限变化后禁止继续读取旧凭据或新截图。
- [ ] 验收：成功和失败任务均能定位到具体步骤；不同 owner/Bot 不能读取未授权证据；密码、token、验证码不进入公共日志或模型上下文。
- [ ] 验收：截图和录像按授权采集，人工接管及受保护界面停止采集；返回文件可打开且符合访问范围，不把路径文字当作已交付文件。
- 依赖：A02/A03/A05。

## 阶段 B：网页强操控

### B01 浏览器、标签页和登录态

- [ ] 开发：自然语言打开/查找/切换/关闭网页，前进后退刷新，新窗口归属管理；继续使用 Bot 专属 profile。用户 Chrome 登录态借用是独立显式授权能力，补中继控制端认证和目标范围。
- [ ] 验收：“打开测试后台”“切换到订单页”“关掉你开的页面”均作用于正确目标；重启后允许保留的专属登录态仍有效。
- [ ] 验收：无 token、过期 token、错误 Bot 的中继连接被拒绝；借用未授权标签页失败；退出任务不关闭用户页。
- 依赖：A02–A04。

### B02 页面观察与精确元素引用

- [ ] 开发：读取文本、角色、名称、状态、链接和可操作元素；支持区域读取、iframe、Shadow DOM 和必要截图；引用带文档/快照归属，不混合不同后端生命周期。
- [ ] 验收：包含同名按钮、嵌套 iframe、Shadow DOM 的 fixture 能定位指定控件；导航/DOM 替换后旧引用拒绝执行，重新观察后才可操作。
- [ ] 验收：部分读取和不完整树必须标记；不存在、不可读取、暂未加载不能混为一个“没有”。
- 依赖：B01/A05。

### B03 表单、点击和页面交互

- [ ] 开发：点击/双击/右键/悬停、填入/清空、中文输入、勾选、下拉、日期、快捷键、滚动、拖拽；动作前检查禁用、遮挡、可编辑性及位置稳定性。
- [ ] 验收：复杂表单填写后逐字段核对预期值；中文、换行、emoji、长文本无漏字/重复；“先别提交”时提交计数始终为零。
- [ ] 验收：被遮挡/禁用的按钮不误点；动态位移和拖放用真实事件验证；不可操作时给出原因，不用改 DOM 值伪装成功。
- 依赖：B02/A03/A05。

### B04 弹窗、条件等待与结果读回

- [ ] 开发：处理网页 alert/confirm/prompt、新标签页、登录跳转；按文字/URL/元素/状态等待，受取消和任务截止时间约束。
- [ ] 验收：异步保存/导出延迟随机变化时，以实际结果结束等待；业务失败提示出现时任务失败或等待处理，不显示成功。
- [ ] 验收：确认类弹窗不能默认同意危险动作；超时和用户停止后不继续操作新页面。
- 依赖：B03/A04/A05。

### B05 文件上传、下载和数据整理

- [ ] 开发：上传仅限授权附件/工作区文件；下载关联目标任务，处理重名与失败；提取多页数据生成 CSV/XLSX 等明确约定格式并交付。
- [ ] 验收：测试表上传后页面显示正确文件名和处理结果；下载结束后文件存在、能解析且内容匹配，不能只看按钮已点。
- [ ] 验收：分页筛选结果与 fixture 真值一致，无漏页/重复；越权路径、取消上传、下载失败不产生虚假成功。
- 依赖：B02–B04/A06。

## 阶段 C：电脑强操控

### C01 应用、窗口和能力自检

- [ ] 验收：普通/DPI 缩放/多显示器场景点击匹配截图位置；窗口移位正确映射，尺寸或显示布局变化后旧坐标拒绝；放大截图不悄悄改变完整图坐标系。
- [ ] 验收：中文、换行、emoji 和长文本在测试应用准确输入；拖文件到测试应用完成后核对对象；取消后无残留按键。
- 依赖：C01/C02/A04/A05。

### C04 后台操作与前台接管

- [ ] 开发：支持后台的动作不抢鼠标焦点；后台不可用时停止并说明。仅在具体授权后转前台，结束后尽可能恢复用户焦点，恢复失败如实报告。
- [ ] 验收：“在后台处理，我继续用电脑”时不偷偷激活目标；后台失败不继承上游自动 takeover。用户拒绝接管后不发送前台动作。
- [ ] 验收：用户活动和紧急停止按实际平台能力检测；停止后无新输入。平台不支持后台/全局 Escape 时明确暴露，不承诺同等行为。
- 依赖：C02/C03/A03/A04。

### C05 菜单、文件对话框和跨应用流程

- [ ] 开发：识别系统文件选择器、另存为、确认框、菜单；通过剪贴板/授权文件衔接网页与桌面应用，处理同名文件及覆盖确认。
- [ ] 验收：“打开下载的报表，另存为 PDF”完成后产物可打开、内容匹配、路径正确；取消覆盖时原文件保持不变。
- [ ] 验收：网页数据复制到指定桌面窗口而非当前任意窗口；必要的剪贴板临时内容不泄漏到其他 Bot，恢复策略不覆盖用户期间的新复制内容。

### D02 读屏、截图与常用操作

- [ ] 开发：打开 App、读取屏幕元素、截图、点击/长按、滑动、返回/主页；绑定设备、当前 App 和观察证据；结合 Pinky 改善文本输入。
- [ ] 验收：在测试 App 完成搜索→详情→读取结果，结果与 fixture 真值一致；同名控件、页面变化、横竖屏变化后无旧坐标误点。
- [ ] 验收：中文、换行、emoji、长文本准确输入且读回；无法验证时明确报告，不以 ADB 返回 0 替代验收。
- 依赖：D01/A05。

### D03 手机审批与人工接管

- [ ] 开发：敏感 App/字段、发送/删除/提交通过统一权限入口；登录、解锁、验证码请本人处理；人在镜像或设备接管后暂停 Bot，交回后重新观察。
- [ ] 验收：测试发送动作未确认前计数为零，确认后仅一次；审批期间换页面/收件人后旧审批不能执行；不读取或持久化密码/验证码。
- [ ] 验收：“我来登录”“好了，你继续”可完成交接；后台/断线/无人工响应不得自行批准。设备触摸检测未支持时明确要求显式接管，不虚称自动检测。
- 依赖：D02/A03/A04/A06。

## 阶段 E：全对话长任务与恢复

### E01 暂停、停止、纠正、追加和进度

- [ ] 开发：区分“停一下”“取消任务”“换成另一个账号”“做完后再整理汇总”；映射持久任务状态和队列，纠正影响后续动作，不能把取消当排队提示。
- [ ] 验收：任务执行中发上述语句，各自状态转换正确；暂停后“继续”可恢复，取消后不能被迟到结果重新激活；追加任务不打断当前任务。
- [ ] 验收：明确停止消息到达宿主后 1 秒内进入停止/正在停止状态，之后不派发新动作；不可中断的在途原生调用如实显示，不能宣称已撤回。
- 依赖：A01/A04/A05。

### E02 受限多步工具执行

- [ ] 开发：采用受限脚本或等价受控批量工具执行，一次完成可预测步骤；每个子调用均检查权限、取消和目标归属。设置显式内存、运行时间、输出量、并发限额，不给脚本任意宿主文件/网络/进程权限。
- [ ] 验收：多页读取、筛选和整理一次批处理完成，结果与逐项真值一致；记录模型请求次数、动作数、耗时和 tokens，与逐步基线比较，不预先承诺节省比例。
- [ ] 验收：脚本尝试直接访问 process/任意网络/未授权工具被拒绝；死循环、超额内存和取消不阻塞 UI；批处理中的危险动作仍暂停等待批准。
- 依赖：A03–A05/B02/C02/D02。

### E03 安全续做与应用重启恢复

- [ ] 开发：持久化任务目标、步骤、动作意图、结果、待确认状态及证据引用；“继续刚才没做完的”先核对实际目标状态。原有 Markdown handoff 不能替代动作账本。
- [ ] 验收：分别在动作前、动作后结果保存前、审批等待中、下载中关闭隔离进程再启动，任务状态可解释且不丢失已记录结果。
- [ ] 验收：审批/控制租约重启后不可无条件复用；未明确安全的修改不自动重放；已发送消息、已提交表单不会重复执行。
- [ ] 验收：恢复连接、查询状态与重新发送模型/业务请求分开；未知付费结果不自动重发。
- 依赖：A05/A06/E01。

### E04 长上下文和结果交付

- [ ] 开发：按需加载工具、裁剪重复截图/工具输出、压缩旧过程，任务目标和授权状态独立保存；完成时交付文件/截图/验证结论及遗留项。
- [ ] 验收：至少 30 个动作的隔离长任务，经历一次上下文压缩后仍保留“先别提交”等约束，能继续当前步骤；不把压缩摘要当新授权。
- [ ] 验收：失败任务给出已完成/未完成及原因，不说全部完成；输出附件可打开，用户能在对话中追问证据。
- 依赖：A06/E02/E03。

## 阶段 F：打包、平台矩阵与端到端验收

### F01 源码移植与发布资源

- [ ] 开发：记录采用文件的上游版本、修改点、许可证/NOTICE；适配 Node/Electron、原生辅助进程和跨平台资源；不要求用户安装参考项目。
- [ ] 验收：干净检出且没有 `references/` 的构建机能完成对应平台打包；安装后的 App 不依赖开发目录或用户全局 OMP/Pinky/Pi/agent-desktop。
- [ ] 验收：辅助进程退出、权限变更重启、版本不匹配、签名/资源缺失均明确失败；原生模块故障不把整个会话伪装成完成；卸载/退出不遗留任务控制。
- 依赖：所有实际移植项；每个平台单独记录。

### F02 六个全对话验收场景

所有入口从实际对话 UI 发起，不直接调用内部 API 代替用户行为。自动化夹具可以准备数据、注入故障及核对结果，但不得用其绕过待验证的操控步骤。每个场景在隔离数据上连续执行三次，分别记录成功、失败和原因；不能只展示成功那一次。

| 场景 | 对话输入与步骤 | 必须满足的验收结果 |
| --- | --- | --- |
| S1 后台订单 | “找出本周未发货订单并导出”→专用已登录测试站点→筛选→下载 | 行数/订单 ID 与真值一致、文件可解析、无订单修改、证据指向正确账号 |
| S2 复杂表单 | “按附件填好，先别提交”→文字/日期/下拉/文件/iframe→用户确认提交 | 确认前提交 0 次，确认后恰好 1 次；改变关键字段后旧批准失效 |
| S3 网页到桌面 | “下载这份表，用桌面应用打开并另存为 PDF” | 下载/窗口/文件均匹配目标；PDF 能打开；用户其他窗口及原文件不被改动 |
| S4 Android 查信息 | “在这部手机的测试 App 查物流并把结果给我” | USB 真机完成打开/输入/滑动/读取，结果正确；第二部手机调用 0 次 |
| S5 人工接管 | 任务中说“我来操作”→本人改字段→“好了，你继续” | 接管期间 Bot 无修改动作；交回后重新观察，保留用户修改，不照旧内容覆盖 |
| S6 失败后继续 | 在提交已发生但回包丢失、设备断线、App 重启三处注入故障→“继续刚才的” | 核对现状再继续；提交/发送无重复；无法判定时明确等待人工而非猜成功 |

- [ ] 验收：六场景在本期声明支持的平台通过，保存对话、任务/动作 ID、最终产物和脱敏截图/日志。
- [ ] 验收：分别执行拒绝授权、过期引用、两 Bot 争用、异常取消和越权证据读取反例，均按契约拒绝。
- [ ] 验收：平台矩阵明确记录 macOS/Windows/Linux 的浏览器、原生桌面、Android USB、后台输入、全局停止能力；未验证平台不得发布“全面支持”。
- [ ] 验收：发布记录列出每个场景的总耗时、模型请求数、工具调用数、失败次数、用户接管次数、输入输出 tokens；数据用于优化，不宣称已达到“最强”。
- 依赖：A–E、F01。

## 实施顺序与完成门槛

1. A01–A06：先定共用目标/权限/结果契约，建立拒绝与取消边界。
2. B01–B05、C01–C05、D01–D03：按独立表面实施；不能未经 A 阶段就暴露高权限工具。
3. E01–E04：接入对话控制、多步执行、安全续做与上下文管理；基础状态在 A 阶段先建立。
4. F01/F02：对应平台打包实测后才能标完成。迁移时更新受影响旧契约测试，禁止靠降低验收或隐藏异常过关。

每项只有代码、相关回归检查、隔离实际表面验证和交付证据齐全后才能勾选。缺测试设备/平台权限时记录阻塞条件，保留未完成状态。

## 本期明确不做

- `/指令` 产品入口、要求用户自行运行终端命令的常规操作流程。
- iPhone 全面操控、手机端独立 Agent、Android 副屏/后台锁屏执行、Wi-Fi/异地设备连接。
- 独立虚拟桌面、无人值守付款、自动解除 OS 安全权限或自动输入用户验证码。
- 完整移植 OMP/Pi SDK/TUI、第三方自动更新、个人配置扫描和个人密钥自动导入。
- Birdview 架构图、复杂编程/调试工具、自动生成技能、全量录像回放；已有相关功能不因本清单被删除。
- 改写现有网关账本策略、自动重发失败模型请求、默认共享用户 Chrome 登录态。
