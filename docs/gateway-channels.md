# 渠道与模型管理

## 借鉴与边界

参考 [Magpie 渠道/账户设计](https://github.com/yetone/magpie/blob/main/docs/subsystems/providers-accounts.md) 和 [路由设计](https://github.com/yetone/magpie/blob/main/docs/subsystems/gateway-routing.md)：渠道持有上游地址和凭据，模型公开名独立于上游名，发现模型不等于发布模型，停用与删除分开处理。实现沿用本仓库 TypeScript Worker、D1、账号权限和积分账本，不复制 Magpie 的 Go 代码，也不引入个人订阅登录发现。

管理网页的“渠道与模型”负责配置，实际 `/v1/ai/*` 请求使用同一持久化配置。支持现有 OpenAI-compatible Chat Completions / Responses，不声称提供 Anthropic/Gemini 协议转换。每个公开模型明确绑定一个渠道；不自动重试、负载均衡或故障切换已经发出的计费请求。

## 配置生命周期

- 渠道：稳定 ID、名称、HTTPS API base、启用状态、只写 API key。
- 模型：公开 ID、显示名、渠道 ID、上游模型名、协议、价格版本、输入/缓存输入/输出价格、上下文与输出限额、启用状态。
- 所有价格为每百万 token 的整数微积分；无默认免费价格，零价必须由运营者明确输入。
- 页面修改先暂存，填写原因后保存整份配置。保存成功后新请求直接读取新配置，不重启服务。已经预占的请求使用原请求的计价快照，不追溯改账。
- 模型发现只请求已保存渠道的 `/models`，不调用付费推理，不自动发布或猜价格。返回模型列表不证明推理、余额或协议能力可用。
- 停用渠道使其模型不再接收新请求。删除渠道前须移除模型引用。至少一个模型有效启用时，默认模型必须指向其中一个。

## 凭据与安全

API key 在 D1 中使用 AES-GCM 加密；密钥从服务器 `BETTER_AUTH_SECRET` 通过域分离派生。备份数据库时也必须备份认证秘密，单独更换该秘密会导致旧渠道凭据无法解密。认证秘密本身不进入数据库、Git、网页或日志。

GET 响应仅包含 `hasKey`，不返回明文、密文或 key 后缀。未填写 key 表示保留同 ID、同 URL 的旧 key；更换 URL 必须明确重新输入 key，防止无意把旧凭据送往新主机。保存、退出和会话失效后页面清除暂存的 key。

仅运营者可配置渠道。运营者是服务器信任边界：允许其选择 HTTPS 内网上游，因此此功能不是任意不可信租户的 URL 代理。URL 拒绝用户名密码、query、fragment、非 HTTPS；不跟随重定向。DNS/网络访问控制由服务器部署环境约束，不能将字符串检查声称为 DNS rebinding 防护。模型发现有请求时限、响应大小和条目数上限，错误不回传上游正文或秘密。

## API

所有接口使用账号 Bearer 会话，并逐次验证运营者名单。未登录 401，普通账号 403。普通模型令牌与安装凭据不提供管理权限。

| 方法 | 路径 | 响应/含义 |
| --- | --- | --- |
| GET | `/v1/operator/channels` | `{revision,channels,models,defaultModel}`，无秘密 |
| POST | `/v1/operator/channels` | `{revision,reason,channels,models,defaultModel}` 完整保存；返回新目录 |
| POST | `/v1/operator/channels/:id/probe` | `{models:string[],latencyMs}`，仅查询已保存渠道模型列表 |

保存采用整份目录乐观并发版本。`revision` 过期返回 409，不覆盖其他管理员的新配置。网络结果未知时先重新读取目录，不生成盲目覆盖请求。变更版本、操作者、原因和时间与配置一起原子提交。上限为 50 个渠道、200 个公开模型，保存体最大 256 KiB。

## 原配置切换

第一次保存前，已有环境变量/本地配置的单上游作为 `legacy` 渠道展示，现有客户端继续使用相同公开模型 ID。首次保存把配置切换到持久化目录；之后即使保存空目录，也不回退到旧环境变量重新开启模型。旧环境变量只用于尚未迁移的部署，运营者名单仍由服务器配置掌管，网页不能自行加管理员。

本地 CLI `status` 的 capabilities 来自启动快照，不能用它判断网页修改后的模型目录；运营者当前状态和 `/v1/account/ai` 使用实际运行时配置。

## 客户端协作

桌面和手机无需上游 key。公开模型结构与原账号 API 保持一致；上游地址、内部模型名和渠道秘密不会加入公共模型响应。需要改公开模型 ID 时，由运营者协调使用方，不能悄悄把历史请求改成新模型。接口变更、部署版本和验证记录通过后端 Git 分支交付。
