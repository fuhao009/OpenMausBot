# 网关管理后台开发规格与验收标准

> 状态：待开发验收规格，不代表功能已经实现。本文规定目标导航、业务规则和交付门槛；历史任务中的部署状态不作为本次验收证据。

## 1. 目标、边界与依据

建设面向网关运营者的统一 `/admin` 后台，完成渠道配置、模型发布、用户管理、积分运营、请求复核与系统维护闭环。后台不读取桌面 bot、对话正文、工作区文件，不承担桌面设备管理。

相关资料：

- [原后台设计](gateway-admin-design.md)：历史设计与接口线索。
- [网关第一版服务端任务](gateway-v1-server-tasks.md)：上游协议、请求错误与结算约束。
- [内测服务端待办](gateway-beta-server-todo.md)：任务计费、待复核、用户停用、重置密码要求。

上述文档存在阶段差异；开发开始时须核对实际路由、数据库迁移和测试。历史资料提及的 `gateway-channels.md` 当前缺失，不能以其作为实现依据。本文新增接口名为建议契约，须先与现有接口核对再定稿，禁止重复建设同义接口。

### 1.1 本次必须交付

| 一级栏目 | 子栏目 | 主要产出 |
| --- | --- | --- |
| 概览 | 运行概况、待处理事项 | 可核对的运营指标、可跳转的处理入口 |
| 渠道与模型 | API 渠道、上游模型库、对客混合模型 | 上游接入、能力维护、面向客户的模型发布 |
| 用户管理 | 用户列表、权限、停用恢复、密码重置 | 用户查询与完整账号生命周期控制 |
| 积分与请求 | 积分分配、流水、请求、待复核、计费 | 账本追溯、幂等操作、人工复核、定价与成本统计 |
| 系统管理 | 基础设置、管理员改密、审计、服务状态 | 安全维护、配置发布和运行诊断 |

不包含：支付充值、退款支付通道、发票、订阅账号、多 key 轮换、自定义请求头、代理、协议转换、邮件找回、外部告警、设备管理和账号物理删除。停用账号不等于删除账号。本次不能以“只做前端页面”代替后端权限、持久化和审计。

### 1.2 核心原则

1. 上游限于 OpenAI 兼容的 Chat Completions / Responses；不同协议不能靠改模型名称互相兼容。
2. 客户侧只显示对客模型，不暴露渠道密钥、上游地址和内部路由规则。
3. 可能已到达上游的请求不自动重放、不跨渠道自动重试；用量不确定进入待复核，不自动退款。
4. 所有金额使用整数微积分，`1 积分 = 1,000,000 微积分`；金额计算不使用二进制浮点数。
5. 历史账本、请求价格快照和审计不可被配置修改重写。
6. 管理操作由服务端鉴权，浏览器隐藏按钮不是权限控制。

### 1.3 页面优先级与栏目归属

保留五个一级栏目；以下九个页面是功能交付单位，不增加九个顶级导航。P0 必须首批交付，P1 必须后续交付，不是可选项。新增细则与验收见第 13 节，可勾选清单见第 14 节。

| 页面 | 一级栏目 | 优先级 | 核心功能 | 核心验收 |
| --- | --- | --- | --- | --- |
| 概览 | 概览 | P0 | 请求数、扣费、毛利、待复核卡片；近 7 天趋势；待处理区 | 数字和账本一致；空数据不显示 NaN |
| 用户 | 用户管理 | P0 | 列表、搜索、筛选、详情抽屉；加减积分、停用恢复、删除、重置密码；批量加积分；个人并发上限 | 分页不重不漏；批量三人金额及审计正确；扣减不产生负余额 |
| 请求日志 | 积分与请求 | P0 | 全局筛选、详情抽屉、批量结算、CSV 导出 | 编号前 8 位可命中；成功结算后对应冻结归零；导出合计与页面一致 |
| 渠道 | 渠道与模型 | P0 | 连通测试、健康状态、近 1 小时失败率、发现上游模型一键创建 | 错误密钥显示鉴权失败；删除被引用渠道返回 409 |
| 模型与定价 | 渠道与模型 | P0 | 积分/百万 token 输入、精确换算、用量扣费预览 | 0.55 存为 550000 微积分/百万 token；0.5500001 被拒绝 |
| 智能计费 | 积分与请求 | P0 | 四个标签页；毛利和倍率百分比输入；调价历史 | 50% 为 5000 基点；33.333% 被拒绝 |
| 积分 | 积分与请求 | P1 | 全局流水、兑换码 | 同码并发兑换仅一次成功；数据库无兑换码明文 |
| 审计 | 系统管理 | P1 | 只读运营者操作日志 | 全部变更可追溯；无密码和密钥明文 |
| 设置 | 系统管理 | P1 | 运营者管理、注册策略、公告、全局默认、维护模式 | 保留最后一个运营者；维护时推理返回 503 且不扣费 |

P1 的审计页面不延后 P0 的审计落库；P1 的全局设置页面不延后 P0 所需默认配置与个人并发控制。

## 2. 公共界面与交互规范

### 2.1 导航和页面框架

- 桌面端左侧五个一级栏目，展开后显示表中子栏目；顶部显示环境、当前管理员和退出入口。
- 详情页通过列表进入，并保留筛选、排序、游标与返回位置。刷新后可恢复当前栏目；URL 不携带密码、密钥、临时密码。
- 窄屏使用折叠菜单，表格允许局部横向滚动，不能让整页横向溢出；危险操作按钮不得因裁切无法操作。
- 用户权限、停用恢复、密码重置可以采用用户详情标签页或操作抽屉，但导航与面包屑须能定位所属功能。
- 跨栏目跳转使用稳定 ID；概览中的待复核数字跳转后必须携带同口径筛选条件。

### 2.2 列表、表单与错误

- 列表服务端分页，默认每页 20 条，最大 100 条；固定排序字段加唯一 ID 作为次序，禁止前端拉全量再分页。
- 时间存储 UTC，界面明确时区；时间筛选采用左闭右开区间。金额精确展示至最多六位小数，不把小额非零余额显示为零。
- 区分加载中、无数据、筛选无结果、无权限、接口失败；失败不显示为零或空列表。
- 表单说明必填项、单位、限制；保存中防重复提交；失败保留非敏感输入。离开未保存表单时提示。
- 危险操作确认框显示对象、影响、原因及最终提交按钮；密钥和密码不进入通用表单缓存。
- 401 跳转登录，403 展示权限不足，409 提示状态变化并重新读取，429 展示等待提示，5xx 不假报成功。
- 成功后以服务端返回值或重新查询结果更新页面，不只修改前端状态。

### 2.3 公共验收

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| G-01 | 依次访问全部子栏目并刷新详情页 | 导航、面包屑、选中项正确，无空壳页面；刷新仍可定位对象 |
| G-02 | 使用 1440×900、768×1024、390×844 视口 | 主操作可达、弹窗可滚动、无整页横向溢出 |

| G-04 | 模拟 401、403、409、429、500 与断网 | 状态和文案符合约定；未知结果不显示成功、不新建重复操作 |
| G-05 | 创建超过两页同时间戳记录并翻页 | 固定数据集内无重复、无遗漏；筛选变更重置游标 |

## 3. 身份、权限与关键数据约束

### 3.1 权限模型

本期采用普通用户和运营管理员两类身份，不建设自定义角色编辑器。管理员权限变更仅允许具备授权能力的管理员操作；初始管理员由服务器 CLI 显式授权，注册不能获得管理权限。

用户的三个状态必须独立：账号状态（正常/停用）、AI 使用状态（未开通/启用/停用）、管理员身份（是/否）。账号恢复不能自动开通 AI 或恢复已撤销的管理员权限。

- 禁止停用、撤销或通过并发操作移除最后一个有效管理员，服务端事务保证。
- 禁止管理员在后台对自己执行停用或管理员身份撤销；通过其他有效管理员办理。
- 停用账号、重置密码、修改密码后，旧会话及旧模型令牌必须在下一次鉴权时失效。
- 已派发的推理请求仍完成用量收集与结算，不因停用或撤销会话直接退款。
- 强制改密状态只能访问改密、当前安全状态和退出接口，不能调用 AI 或管理业务接口。

### 3.2 数据对象与不可变信息

复用现有表和字段；下列是逻辑要求，不强制一对象一新表。

| 对象 | 必需信息 | 约束 |
| --- | --- | --- |
| 渠道 | ID、名称、协议、基础地址、密钥引用、启停状态、版本、探测时间及结果 | 不回传明文密钥；历史引用不可失效 |
| 上游模型 | ID、渠道 ID、真实模型名、协议、能力、上下文/输出限制、采购价版本、启停状态 | 同渠道及协议下模型身份唯一 |
| 对客混合模型 | 稳定公开 ID、展示名、协议、路由规则、候选模型、计费版本、发布版本、状态 | 发布原子生效；请求固定版本 |
| 用户 | ID、邮箱、账号状态、AI 状态、管理员身份、强制改密状态、版本 | 邮箱查询结果不默认透露给普通用户 |
| 钱包/流水 | 用户 ID、可用/预占余额、变更额、变更前后值、业务类型、关联请求/操作 ID | 整数、原子更新、不可修改已记账流水 |
| 请求 | ID、用户、对客/实际模型、路由版本、用量、预占、已扣费、结算状态、成本状态 | 保存计价快照，不保存对话正文作为管理查询内容 |
| 审计 | 操作者、对象、动作、操作 ID、脱敏变更、结果、时间、关联请求 | 不含秘密；业务成功记录与关键变更原子落库 |

金额在 JSON 中若可能超出安全整数范围，使用十进制整数字符串并统一契约；客户端不得隐式转成不安全的 Number。

### 3.3 幂等与并发

- 积分增加、结算、权限修改、停用恢复、密码重置、配置发布均有 `operationId`。
- 同操作者同业务范围内，相同操作 ID 和相同参数只执行一次；同 ID 不同参数返回 409。
- 网络超时后先查询操作结果，再使用原 ID 重试；不能把“没收到响应”当作“服务端没执行”。
- 编辑和发布带对象版本号；过期版本返回 409，不能覆盖他人修改。
- 临时密码仅首次成功响应显示；同 ID 重试返回已完成状态，不再次返回秘密。首次响应丢失时允许管理员明确发起一次新重置，旧临时密码立即失效。

## 4. 概览

### 4.1 运行概况

默认展示今日，可选择近 7 日、近 30 日、自定义区间。返回数据包含统计起止时间、时区和生成时间。

| 指标 | 口径 |
| --- | --- |
| 用户数/AI 启用用户数 | 当前时点账号总数及正常且 AI 启用的账号数，不冒充区间新增数 |
| 请求数 | 区间内创建的账本请求数；预占前拒绝的 HTTP 调用单独统计，不混入 |
| 推理成功率 | 已结束推理中成功完成的比例；与结算成功率分开，分母为零显示“—” |
| 已扣积分 | 区间内账本扣费事件净额，包含部分扣费及冲正；不是预占总额 |
| 当前预占积分 | 当前全部未释放预占余额，不受请求创建时间筛选误导 |
| 待复核数 | 当前未解决的复核请求数，另列最久等待时长 |
| 已知采购成本 | 仅成本已知记录，展示币种与未知成本请求数 |
| 渠道状态 | 启用数、最近探测失败数、未探测数；注明探测时间 |

不同币种成本不得直接相加；没有明确积分兑货币换算口径时，不显示货币毛利。指标查询失败显示不可用，不显示 0。

### 4.2 待处理事项

固定类别：待复核请求、不可用渠道、无可用候选的已发布模型、缺失采购价或计费配置。按严重程度、最早发生时间排列；每类有数量、影响说明、最近检测时间和处理入口。采用实时或缓存派生结果，不允许“已读”隐藏仍未解决的风险。

### 4.3 验收

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| O-01 | 固定时钟，准备跨日请求、部分扣费、冲正与预占记录 | 每个指标与独立账本计算一致；时间边界不重复 |
| O-02 | 无请求、统计失败、成本未知三种情况 | 分别显示空值口径、失败、未知，不互相混淆 |
| O-03 | 从待复核卡片进入列表并完成一笔复核 | 筛选正确；刷新概览后数量及预占同步变化 |
| O-04 | 启用渠道尚未探测，另一渠道探测失败 | 分别显示未探测和失败，不将启用等同健康 |

## 5. 渠道与模型

### 5.1 API 渠道

列表显示名称、协议、脱敏地址、启停状态、关联模型数、最近探测结果、更新时间。支持按名称、协议、状态筛选。

新增/编辑字段：名称、OpenAI 兼容协议能力、HTTPS 基础地址、密钥。密钥输入空值表示保持不变；更换为显式操作；读取接口仅返回是否配置及掩码。浏览器不直接调用上游。

服务端必须限制可访问地址，防止 SSRF：拒绝回环、链路本地、云元数据和未经部署白名单许可的私网目标，校验解析后的地址，禁止重定向。网关自身部署在局域网不等于可以访问任意内网地址。

提供两种状态明确的检查：配置检查（不产生推理）和最小推理探测（可能产生上游费用，操作前提示）。探测由服务端执行，设超时与输出上限，记录脱敏错误类别，不自动轮询产生付费调用。探测费用不能记入任意用户钱包。

停用渠道仅禁止新请求选中；已派发请求按原快照结算。若会使已发布对客模型没有可用候选，普通停用返回冲突并列出影响模型；显式“停用并将受影响模型下架”须二次确认并原子完成。存在历史引用的渠道只能归档，不能级联删除历史数据。

### 5.2 上游模型库

上游模型归属于渠道，字段包括真实模型 ID、显示名、协议、上下文上限、最大输出、文本/图像/工具/流式能力、启停状态、采购价与币种。

- 支持手工创建；渠道提供模型发现接口时，可导入为草稿，不自动发布。
- 同名模型在不同渠道允许存在；身份使用内部 ID，不能仅按模型名关联。
- 模型发现只证明存在，不证明工具、图像、缓存或上下文能力；未知能力显示未确认。
- 输入、输出、缓存读取、缓存写入价格分别配置，单位明确为每百万 token；未知和零价是不同状态。
- 无法可靠计量或不支持的计费维度，不允许填零伪装为免费。
- 修改采购价生成新版本，不重新计算历史成本；修改能力必须检查已发布混合模型是否仍满足承诺。

### 5.3 对客混合模型

对客混合模型是稳定公开模型 ID 对一个或多个上游候选的封装。公开 ID 在被请求引用后不可更名或复用；展示名可改。

支持固定候选与任务分级两种路由。任务分级沿用现有简单、标准、复杂分类逻辑，配置对应候选及优先级；不新增另一套分类算法。候选必须协议一致并满足对客能力承诺，不允许 Responses 候选承接 Chat 请求。

编辑页包含：基本信息、协议与能力、候选选择、任务档位映射、计费策略引用、默认模型标记、发布前检查、版本记录。配置流程为草稿 → 校验 → 发布 → 下架；发布失败保留草稿，不能影响当前版本。

发布必须满足：至少一个可用候选；所有可达档位均有路由；渠道启用且有密钥；模型限制合法；计费配置完整；采购价缺失时须按既有计费策略明确是否阻止发布，不允许静默按零成本处理。对于依赖成本的计费策略，缺采购价必须阻止发布。

每个协议最多一个默认对客模型。默认切换与发布原子完成。回滚是把旧内容发布成一个新版本，不修改旧记录。请求开始时固定路由及价格版本；发送前可排除已停用候选，一旦可能发送到上游，不切换候选重放。

### 5.4 验收

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| M-01 | 保存渠道，刷新页面、读取接口、检查日志 | 密钥可用但无明文泄漏；空密钥保存不清除已有值 |
| M-02 | 提交 HTTP、元数据地址、重定向至私网的探测目标 | 在实际访问受限目标前拒绝，错误可读且脱敏 |
| M-03 | 同名模型分别归属两个渠道 | 可独立保存、筛选与引用；同渠道重复身份被拒绝 |
| M-04 | 导入缺能力/价格模型 | 保持草稿或明确未知，不能自动发布为全能力、零成本模型 |
| M-05 | 发布协议不匹配、档位缺失或无候选模型 | 返回字段级错误，线上版本不变 |
| M-06 | 两个管理员同时发布/切换默认模型 | 仅兼容当前版本的提交成功，每协议最多一个默认 |
| M-07 | 请求运行中改价、下架或停用渠道 | 在途请求保持原快照结算，新请求使用新配置或明确拒绝 |
| M-08 | 假上游收到请求后断网 | 不调用第二候选、不重复派发，按证据结算或进入待复核 |
| M-09 | 发布并回滚一个对客模型 | 客户模型目录只显示可用对客模型；版本递增、历史可追溯 |
| M-10 | 关闭最后可用渠道 | 普通停用返回影响清单；确认联动下架后无失效的已发布模型 |

## 6. 用户管理

### 6.1 用户列表与详情

支持邮箱精确查询、用户 ID 查询，以及账号状态、AI 状态、管理员身份、创建时间筛选。默认分页显示最近创建用户，不读取全部用户。

列表字段：用户 ID、邮箱、邮箱验证状态、创建时间、账号状态、AI 状态、管理员标记、可用/预占积分。详情展示状态变更时间、余额、最近请求和操作审计入口；不展示密码哈希、会话令牌或密钥。

### 6.2 权限

分别提供 AI 开通/停用与管理员授权/撤销。确认框解释影响，原因必填；权限即时由服务端检查，已经打开的管理页面不能继续使用被撤销权限。

### 6.3 停用与恢复

停用账号要求原因和二次确认，阻止新登录，撤销现有会话及模型令牌；已有请求继续结算。恢复仅解除账号停用，不恢复旧会话、令牌，不修改 AI 状态、余额及管理员身份。禁止用停用实现隐式清空积分。

### 6.4 密码重置

管理员不能查看或设置一个可长期复用的用户密码。系统使用密码学安全随机源生成符合服务端密码规则的临时密码，仅在首次成功响应中显示一次，提供显式复制按钮，关闭后不再展示。

重置立即废止旧密码、会话和模型令牌，标记下次登录必须改密。不依赖邮件。临时密码登录只能进入改密流程；完成后旧临时密码失效，建立新会话。停用用户即使被重置密码仍不能登录。

## 7. 积分与请求

### 7.1 积分分配

支持管理员增加、扣减积分及批量增加积分，不提供覆盖余额或直接改账。选择用户后显示当前可用与预占积分，明确选择增加或扣减，输入正数金额和原因；扣减只允许使用可用余额，事务提交时不足则拒绝，不能扣成负数或占用冻结积分。批量增加按用户生成独立操作 ID，逐笔事务和审计，展示成功、失败及结果未知项；未知项先查原操作，不重新生成 ID。

输入为正数，最多六位小数；拒绝负数、零、超精度、科学计数法及超过系统安全范围的值，不能静默取整。增减方向使用独立业务类型。实际结果以事务提交时余额为准。余额更新、流水与成功审计在同一事务提交；任何一步失败均不改变积分。

### 7.2 流水

筛选：用户、业务类型、请求 ID、操作 ID、时间。字段：流水 ID、时间、用户、类型、可用变化、预占变化、变更后余额、关联请求、操作者/系统、原因。

类型至少区分人工增加、人工扣减、兑换码入账、预占、释放、实际扣费、补扣、既有规则允许的冲正。流水不可编辑或删除；纠错必须走已有授权业务并新增反向记录，不能通过数据库覆写余额。

对于钱包任意时间区间，期末可用/预占分别等于期初值加对应流水变化之和。请求扣费必须可以追溯到流水，不能只保存页面显示的总数。

### 7.3 请求

全局请求列表支持用户、账本请求 ID、对客模型、实际模型、渠道、结算状态、错误码、时间筛选。明确区分 HTTP 追踪 ID 和账本请求 ID；已预占请求优先通过 `x-ai-request-id` 查询。

列表字段：请求 ID、用户、模型、创建时间、推理结果、结算状态、预占、已扣费、待释放金额、成本状态。详情包含路由版本、计费版本、输入/输出/缓存用量、结算原因、脱敏错误、关联流水与审计。

推理成功/失败与结算状态是两个维度：失败请求可以零元结算，也可以带可信用量扣费；不能把 `settled` 显示成“推理成功”。未知用量不能显示为 0。不得在详情中输出上游原始响应正文、用户提示词或工具参数。

### 7.4 待复核

全局显示所有未解决复核请求，支持按用户、原因、渠道、时间筛选，默认最早未处理优先。展示等待时长、证据是否完整、原预占、剩余冻结、已扣费与建议动作。

单笔流程：打开详情 → 查看证据 → 输入最终总扣费及原因 → 展示本次补扣/释放差额 → 二次确认 → 原子结算 → 刷新余额和状态。

必须兼容已经部分扣费的请求：

- “最终总扣费”与“本次扣费”不可混用。
- 本期人工复核不得额外动用未预占的可用余额：最终总扣费下限为已扣费，上限为已扣费加当前剩余预占。
- 无已扣费时，最终总扣费为零表示全部释放；已有扣费时，“释放剩余预占”不等于退回已扣费。
- 如需退回已扣金额，须使用独立已授权冲正业务；本页不提供隐式退款。
- 自动结算路径按既有可信 usage 与补扣规则处理，不被人工上限规则替代。

批量操作本期仅允许“释放剩余预占”，不得命名为一概“零结算”。预览逐笔显示已扣费及释放金额；每笔独立操作 ID、事务与审计。部分失败展示逐笔结果，仅重试失败且结果已确定的条目；未知结果先查原操作。自动结算与人工结算并发时只允许一个状态转换生效。

网络错误、客户端断开、请求超时并不自动构成零扣费证据；界面不能预选“全部退款”。

### 7.5 计费

分为对客计费策略、上游采购成本、统计三部分。

- 复用现有固定费率和任务计费机制；编辑页明确计费模式、适用对客模型、计费维度、舍入规则、预占规则与版本。
- 固定费率按每百万 token 展示输入、输出、缓存读取、缓存写入价格；缓存是否包含在输入 usage 中由协议归一化规则确定，不能重复收费。
- 任务计费显示现有档位规则及参数，不把任务价伪装成 token 单价。
- 提供保存前试算：输入规范化用量/档位，显示预占、最终扣费和计算过程；必须调用与结算相同的计费逻辑。
- 新价格发布后只影响新请求；运行中和历史请求使用原版本。并发发布检查版本号。
- 成本缺失显示未知，不以 0 代替；币种不同分组展示。毛利必须有明确价格及换算版本，展示统计覆盖率。
- 不提供一键重算历史账本，不允许因改价追扣历史用户。

## 8. 系统管理

### 8.1 基础设置

可编辑业务设置采用白名单：后台展示名称、展示时区、注册策略、公告、全局默认并发上限及维护模式。运营者管理复用用户权限体系；全局默认模型引用模型发布配置，不能建立第二份默认值。公开网关地址、版本、邮件能力、AI 配置状态作为只读信息展示，写明配置来源和生效方式。具体规则与验收见第 13 节。

密钥、数据库路径、管理员初始化、TLS 与监听地址通过部署配置管理，不在浏览器提供通用环境变量编辑器。不得展示完整环境变量、文件系统路径或凭据。

可编辑项保存后立即生效并版本化、审计化；展示时区只影响显示与筛选转换，不修改数据库 UTC 时间。只读配置注明是否需重启；不得出现“保存成功但运行时未生效”。

### 8.2 管理员改密

当前管理员输入当前密码、新密码与确认密码；校验与统一账号密码规则一致。修改成功后撤销全部旧会话与模型令牌，包括当前会话，跳转重新登录。失败不清除当前有效会话；密码不进入日志和审计正文。

### 8.3 审计

支持按操作者、对象类型/ID、动作、结果、操作 ID、时间分页查询。详情显示脱敏变更前后摘要和关联请求。

必须覆盖渠道和模型变更、发布/下架、用户权限、停用恢复、密码重置、积分分配、人工结算、基础设置及管理员改密。成功与失败明确区分；认证失败单独记录安全事件，不伪造操作者身份。审计查询本身不产生循环的业务审计。

不提供后台修改/删除审计入口。留存使用现有部署策略，界面显示实际可查询起始时间；不能声称永久保留。查询限制单页和时间范围，避免拖垮业务请求。

### 8.4 服务状态

分层展示：进程存活、数据库读写就绪、迁移状态、定时任务最近成功/失败、渠道最近主动探测结果、配置版本。每项包含状态、采样时间、脱敏原因；缺少观测时显示未知。

`/healthz` 只证明存活，不证明上游能推理、桌面在线或计费正常。页面不得自动持续发起付费推理；手动上游探测复用渠道探测机制。普通账号不能读取内部诊断详情。

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| S-01 | 修改展示名称和时区后刷新并重新登录 | 配置持久生效，UTC 原始数据不变，审计包含版本和脱敏变更 |
| S-02 | 请求修改白名单外配置字段 | 服务端拒绝，不能绕过页面修改部署秘密 |
| S-03 | 改密后使用新旧密码、旧会话和旧令牌 | 仅新密码可重新登录，全部旧凭据失效 |
| S-04 | 执行各类管理写操作并查询审计 | 可由操作 ID 找到操作者、对象、结果；无密码或密钥 |
| S-05 | 模拟数据库异常、未探测上游、定时任务失败 | 分层状态准确，不因 healthz 正常显示全链路健康 |

## 9. 接口交付契约

先核对现有实现，复用已有 `/v1/operator/*` 能力。下面列明需要覆盖的资源面，不宣称路径全部已存在。

| 资源面 | 已有文档线索或建议 | 本次要求 |
| --- | --- | --- |
| 管理员身份 | `GET /v1/operator/me` | 明确 401/403，返回身份与可执行能力，不通过查询用户探测权限 |
| 概览 | 建议 `/v1/operator/overview` | 指标口径、区间、时区、生成时间、待办数量 |
| 渠道/上游模型/对客模型 | 复用实际渠道管理接口，缺失时新增 operator 资源 | CRUD 的适用子集、探测、发布、下架、版本冲突与引用检查 |
| 用户查询与状态 | 原精确查询 `/v1/operator/ai/account`；新增列表/详情能力 | 分页、权限、账号状态、AI 状态分开 |
| 积分 | 复用 `POST /v1/operator/ai/balance` 的增加能力，补充扣减与批量增加契约 | 显式增减方向、可用余额下限、原因、逐笔幂等 ID 与原子记账；不改变旧增加操作语义 |
| 流水 | 新增或扩展 operator 流水查询 | 全局筛选、关联 ID、服务端分页 |
| 请求 | `GET /v1/operator/ai/requests` | 支持全局与用户范围查询，不强制 userId |
| 复核结算 | `POST /v1/operator/ai/requests/:id/settle` | 明确最终总扣费语义、已扣费处理、并发及幂等 |
| 计费 | 复用实际 billing 配置与 metrics 接口 | 版本、试算、发布、成本未知及覆盖率 |
| 系统 | 新增或复用 settings/audit/status 资源 | 白名单设置、审计查询、分层状态 |
| 密码 | 复用认证体系，新增管理员重置能力 | 旧凭据撤销、强制改密、秘密一次展示 |

接口公共要求：

- GET 无写副作用；写操作检查同源与 CSRF，沿用安全 cookie 会话，不将令牌写 localStorage。
- 返回稳定错误码及可定位字段；不得把上游原文直接透传到管理 UI。
- 分页返回 `items` 与 `nextCursor`，游标绑定筛选和排序；错误游标返回 400。
- 每条请求包含可关联的追踪标识；敏感查询参数不得进入访问日志明文。
- 对象不存在与越权响应遵循统一策略，禁止普通账号枚举用户、请求和管理员。
- 前后端共同提交接口字段、金额单位、枚举、错误码、样例及版本兼容说明。

## 13. 新增页面细则与验收

### 13.1 概览：趋势与毛利（P0）

近 7 天趋势包括今日及前六个自然日，按选定时区分桶，缺少记录的日期补零。请求数按创建时间统计，扣费按账本事件统计，图例明确不同口径。卡片与对应趋势使用相同区间和数据快照，响应包含生成时间。

毛利仅对收入、采购成本及换算版本齐全的同一请求集合计算：毛利 = 换算后的收入 − 成本；毛利率 = 毛利 / 收入。收入为零时比例显示“—”，成本或汇率缺失时显示“未知”及覆盖率，不显示虚构的零成本毛利。实时概览和智能计费统计复用同一口径。

- 验收 X-O1：固定时钟构造七天数据，包括跨日、零请求日、零收入与未知成本；逐日合计与账本一致，卡片和趋势一致，页面无 NaN、Infinity 或日期缺口。

### 13.2 用户：删除与个人并发（P0）

删除为逻辑删除加个人信息匿名化，不物理删除账本或请求。删除前必须检查 `reserved = 0`、无待复核请求、无在途请求；删除与新请求准入互斥，避免检查通过后又产生预占。删除撤销会话和模型令牌、禁止登录，保留不可逆的内部关联 ID；邮箱等个人信息从业务记录和审计展示中匿名化。禁止删除自己或最后一个有效运营者。删除有余额的用户必须在确认框明确显示余额及不可再使用的影响，不暗中清零或生成扣费流水。

个人并发上限为正整数或“继承全局默认”；0、负数、小数及超过服务端明确上界的值均拒绝。详情同时显示个人覆盖值、当前全局值及最终生效值。服务端按用户原子执行并发准入；修改后影响新请求，降低上限不强行中止在途请求。恢复继承时不写入一份过期的默认副本。

- 验收 X-U1：对三人分别加 1、2、3 积分，再重试同一批操作；三人只增加一次，三笔流水和审计完整，部分失败可单独重试。
- 验收 X-U2：可用余额 5、预占 10 时扣减 6 被拒绝；并发扣减两笔 4 最多一笔成功，最终可用不为负，预占不变。
- 验收 X-U3：有预占、待复核或在途请求时删除返回 409；满足条件后删除，旧凭据失效，账本条数和金额不变，查询不暴露原邮箱。
- 验收 X-U4：用户 A 上限为 1，用户 B 继承默认 2；保持请求在途时 A 第二笔被拒绝、B 两笔可执行。降低默认值不终止在途请求，个人覆盖不受影响。

### 13.3 请求日志：短编号、批量与 CSV（P0）

支持完整账本 ID 精确查询和至少 8 位前缀查询；不足 8 位提示补全，不执行模糊全表扫描。同前缀命中多个请求时列出所有结果，不能随意跳到第一条。请求列表采用详情抽屉，抽屉可通过完整 ID 定位。

批量结算沿用第 7.4 节的逐笔幂等规则，成功处理的每笔剩余冻结归零。失败项不宣称归零；不要求用户钱包全部预占归零，因为可能存在其他在途请求。

CSV 导出范围为当前筛选的全部结果，不仅当前页。页面同时提供“筛选结果合计”和快照时间，导出复用同一个数据快照及筛选条件，避免导出过程中状态变化导致对不上。大结果分块输出，不在浏览器加载全量；超出配置上限明确拒绝，不静默截断。字段含完整请求 ID、状态、用量、金额及单位；导出权限与列表一致，不输出正文或秘密。文本字段进行 CSV 引号转义及电子表格公式注入防护；金额保留精确十进制值。

- 验收 X-R1：输入前 8 位命中请求；准备相同前缀的两笔时都可见；完整 ID 仅命中对应记录。
- 验收 X-R2：批量结算三笔，成功项剩余冻结为零，流水与审计逐笔齐全；冲突项明确报告且不重复扣费。
- 验收 X-R3：导出跨三页结果，同时产生新请求与结算；CSV 行集合及金额合计与页面同快照筛选合计一致，不受新增数据影响；含逗号、换行、公式前缀的文本不会破坏文件或执行公式。

### 13.4 渠道：失败率与一键建模（P0）

近 1 小时失败率采用滚动 60 分钟内结束的实际上游调用：失败数 / 已结束调用数。失败包括非 2xx、传输错误及流异常；每个上游调用只计一次。未结束调用不进入分母，主动探测单列，不混入业务失败率。没有样本显示“—”；显示样本数和窗口时间，不能把无样本标成健康。

连通测试将 401/403 显示为“鉴权失败”，区分限流、超时、网络、模型不存在与未知错误，禁止展示上游含秘密的原文。修改密钥后旧探测结果标为过期，不继续显示为当前健康。

发现上游模型后可选择并一键创建模型草稿；按渠道、协议、真实模型 ID 去重并逐项显示结果，不绕过能力确认、定价与发布校验。被模型、发布配置或历史记录引用的渠道删除必须返回 409；提供停用/归档替代入口，不级联删除。

- 验收 X-C1：保存错误密钥再探测显示“鉴权失败”；旧健康结果失效，接口与日志不泄漏密钥。
- 验收 X-C2：固定时钟生成窗口内 8 成功、2 失败及窗口外失败，显示失败率 20%、样本 10；无样本显示“—”。
- 验收 X-C3：发现并创建同一模型两次仅保留一份身份记录；删除被引用渠道返回 409，历史引用完整。

### 13.5 模型与定价：十进制精度（P0）

单价输入和显示统一为“积分/百万 token”，存储为“微积分/百万 token”；使用十进制字符串解析，最多六位小数。价格 `0.55` 精确转换为 `550000`，`0.5500001` 必须拒绝，不能四舍五入后接受。仅将每百万 token 的单价换算为微积分，不提前除以百万而丢失精度。

预览输入普通输入、输出及缓存用量，按协议归一化后使用真实结算函数计算，展示价格版本、各项金额、最终合计和舍入规则。免费零价可以显式配置，但不能将缺失价格转成零。

- 验收 X-P1：保存 0.55 后刷新和接口读取均精确；数据库值为 550000；前后端拒绝 0.5500001，价格版本不变。
- 验收 X-P2：一百万普通输入 token、无其他用量时，按 0.55 单价预览扣费为 550000 微积分；真实结算与预览一致。

### 13.6 智能计费：四个标签页（P0）

四个标签页固定为“策略配置”“用量试算”“收益统计”“调价历史”，与模型页共享价格和发布版本，不维护第二套独立单价。

1. 策略配置：显示固定/任务计费模式、任务档位、目标毛利率、倍率及适用模型。目标毛利和倍率为不同策略参数，不能静默相乘；现有引擎若不支持组合，界面强制互斥并拒绝冲突配置。
2. 用量试算：选择模型、档位和用量，展示成本、对客扣费及可计算的毛利，标明草稿/已发布版本，不真实扣款。
3. 收益统计：按时间、模型、档位查询收入、已知成本、毛利及未知成本覆盖率；币种及换算口径沿用概览。
4. 调价历史：只读展示版本、发布时间、操作者、原因、生效范围、前后值；回滚必须创建新版本。

百分比最多两位小数，内部为整数基点，`100% = 10000 bps`。`50% = 5000 bps`，`33.333%` 拒绝。倍率 100% 表示 1 倍、150% 表示 1.5 倍，不是额外加价 150%。目标毛利率范围为 0% 至小于 100%，倍率必须大于 0 并受明确的服务端上界限制。

在收入与成本已统一单位的前提下，目标毛利模式的收入为 `成本 / (1 − 毛利率)`，倍率模式为 `成本 × 倍率`；具体任务计费参数必须沿用已有引擎并在试算中展示，不能用本公式偷偷替换现有模型。缺少必要成本或汇率时阻止依赖成本的策略发布。

- 验收 X-I1：四个标签页均可操作并保留选中模型；保存 50% 后接口和存储为 5000 基点；33.333% 前后端拒绝。
- 验收 X-I2：同单位成本 100，目标毛利 50% 时目标收入为 200；倍率 150% 时收入为 150；两种策略不混算，零收入统计不出现 NaN。
- 验收 X-I3：连续两次调价及一次回滚生成三个新版本，历史显示前后值和操作者，运行中的请求价格不变。

### 13.7 积分：兑换码（P1）

提供兑换码生成、批次列表、状态筛选、停用和用户兑换入口。每码指定正数面额和过期时间，每码全局仅可兑换一次；生成时使用密码学安全随机源并保证足够熵。完整码仅在生成响应中提供一次，后续列表只显示掩码/标识；批量下载必须显式操作且不在服务器持久保留明文文件。

数据库仅保存可查验的安全摘要、批次、面额、到期时间、状态及兑换用户/时间，不存明文或可逆密文。日志、审计和 URL 不包含完整码，兑换接口限流。领取状态更新、钱包入账、流水及审计在同一事务中完成；任一步失败全部回滚。停用、过期、已兑换及用户账号状态均由服务端校验。成功响应丢失时可查原操作结果，不能再次入账。

- 验收 X-W1：两个用户并发兑换同一码，仅一个入账成功，总增加额等于面额；重复提交不重复入账。
- 验收 X-W2：检索隔离数据库、日志、审计及浏览器持久存储，无完整兑换码；过期和停用码无法兑换。
- 验收 X-W3：注入入账失败，码仍未兑换且钱包无变化，恢复后可正常兑换一次。

### 13.8 审计（P1）

第 8.3 节的只读查询扩展覆盖人工扣减、批量分配、用户删除、个人并发、兑换码生成/停用/兑换、注册策略、公告、全局默认和维护开关。P0 上线时这些 P0 操作必须已经写审计，不能等页面上线后再补记录。

- 验收 X-A1：逐类执行新增变更，能按对象及操作 ID 查到结果和脱敏差异；批量操作逐笔可追溯；没有密码、密钥或完整兑换码；修改/删除审计 API 不可用。

### 13.9 设置（P1）

- 运营者管理：显式授权/撤销，沿用最后一个有效运营者和禁止自移除规则，服务端处理并发。
- 注册策略：本期支持开放/关闭注册；关闭后新注册被拒绝，不影响已有账号登录及强制改密，不影响 CLI 初始化管理员。
- 公告：纯文本标题与正文、草稿/发布/撤下；发布后在账号入口展示，不执行 HTML 或脚本。记录版本，刷新后读取真实发布状态。
- 全局默认：全局并发上限为合法正整数，个人覆盖优先；默认模型复用每协议唯一的发布配置，禁止选择不可用模型。
- 维护模式：开启时显示范围及原因，新推理在预占和上游派发前返回 503 与稳定错误码 `maintenance_mode`，无新扣费、预占或上游调用。开关与请求准入有明确原子边界；切换前已准入请求继续正常结算。管理员仍可登录、关闭维护、处理待复核；不影响必要后台结算任务。

- 验收 X-S1：并发撤销最后两个运营者，最多一个成功；始终保留一个有效运营者。
- 验收 X-S2：关闭注册后新注册失败、老用户可登录；公告包含脚本文本时只显示文本；修改全局并发仅影响继承用户。
- 验收 X-S3：开启维护后 Chat/Responses、流式/非流式新推理均返回 503，钱包及上游调用计数不变；在途请求可完成结算，管理员可关闭维护，关闭后新请求恢复。
